# 🎴 LONGSHOT

> **「分の悪い賭けに、全てを懸けろ。」**

ブラフ × イカサマ × 1%の奇跡が交差するリアルタイム心理戦カードゲーム。

![LONGSHOT](public/images/ogp.png)

---

## 🎮 遊び方（ローカルで起動する）

### 必要なもの
- [Node.js](https://nodejs.org/) v18 以上

### 手順

```bash
# 1. リポジトリをクローン
git clone https://github.com/itibo3/longshot.git
cd longshot

# 2. 依存パッケージをインストール
npm install

# 3. サーバーを起動
npm start

# 4. ブラウザで開く
# → http://localhost:3000
```

同じネットワーク内であれば、複数のデバイスで対戦できます。  
CPUとのソロプレイもロビー画面から選択可能です。

## 🃏 ゲーム概要

プレイヤーは手札のカードを「宣言」して場に出す。  
宣言は本当でも嘘でもいい。  
他プレイヤーはそれを **「信じる」** か **「疑う」** かを選ぶ。

- 嘘を見抜けば相手にペナルティ
- 見抜けなければ自分にペナルティ
- しかし——**嘘が「奇跡」で真実になることがある**

さらに各プレイヤーは1試合に1回だけ「イカサマ」を使える。  
何のイカサマを持っているかは本人しか知らない。

**読み合い × 運 × イカサマ。全てが噛み合った時、LONGSHOT が決まる。**

## ⚙️ ゲームルール詳細

### カード構成
- 2〜A（14ランク）× 4スート = 56枚のデッキ
- 各プレイヤーの手札は3枚

### ターンの流れ

```
1. 手番プレイヤーが手札から1枚を裏向きで出し、数字を「宣言」する
   （本当でも嘘でもOK。ただし前のターンより大きい数字を宣言しなければならない）

2. 他プレイヤーが全員同時に「信じる」か「疑う」かを選択

3. 判定:
   a. 全員が信じる    → カードは表を向かずに流れる（真実は闇の中）
   b. 誰かが疑う      → カードを公開して判定

      宣言通り（本当だった）→ 疑ったプレイヤー全員にペナルティ（ライフ -1）
      宣言と違う（嘘だった）→ 宣言したプレイヤーにペナルティ（ライフ -1）
      　　　　　　　　↑ このとき極低確率で LONGSHOT が発動！（後述）
```

### エスカレーション
前のターンで宣言された数字より**大きい数字を宣言しなければならない**。  
Aを超えたタイミングでリセット。数字の圧力が増す中での駆け引きが生まれる。

### ライフシステム
- 初期ライフ: **3**
- ライフ0で脱落
- 最後の1人が勝者

## ⚡ LONGSHOT（嘘が真実になるシステム）

嘘をついて疑われた時、**極低確率で奇跡が発動**する。

```
通常の嘘 →「宣言: 10」「実際: 5」→ 宣言者にペナルティ

LONGSHOT →「宣言: 10」「実際: 5」→ 嘘が真実に！→ 疑った全員にペナルティ
```

- 発動確率は**宣言した数字によって変動**（大きい数字ほど奇跡が起きやすい）
- 発動時は専用の全画面演出＋画面揺れ演出
- 「起きたら語り草になる」1%の奇跡がゲームの緊張感を生む

## 🔮 イカサマシステム

ゲーム開始時に各プレイヤーへランダムで1枚配布。1試合1回限り。  
**何を持っているかは本人しか知らない。**

| イカサマ | 効果 |
|---|---|
| 🃏 **PHANTOM** | 自分のターンで使用。このターン中、他プレイヤーは「疑う」を選べない |
| ❌ **CANCEL** | 相手が PHANTOM を使用した時に発動。PHANTOM を無効化してカードを公開する |

### PHANTOM × CANCEL の読み合い
- PHANTOM を使えば安全にカードを通せる
- ただし CANCEL 持ちが相手なら無効化される
- CANCEL を使ったことは全員に見えるが、それまで黙って温存するプレッシャーが生まれる

## 🖥️ 技術仕様

| 項目 | 内容 |
|---|---|
| フロントエンド | HTML / CSS / Vanilla JavaScript |
| バックエンド | Node.js + Socket.IO |
| 通信方式 | WebSocket（リアルタイム双方向通信） |
| ゲームロジック | 全てサーバーサイドで処理（クライアントは自分の手札のみ保持） |
| CPU AI | ブラフ確率・疑い確率・イカサマ使用判断をパラメータで制御 |
| 再接続 | sessionId管理で30秒以内なら切断後に元のゲームへ復帰可能 |

### セキュリティ設計
- 相手プレイヤーの手札情報はサーバーのみが保持
- クライアントは自分の手札のみ受信するため、ブラウザの開発者ツールを使っても他プレイヤーの手札は参照不可
- ロングショットの発動確率はサーバーサイドで計算・判定

```
longshot/
├── server.js          # サーバー本体（ゲームロジック・Socket.IO）
├── package.json

    ├── index.html     # メインHTML
```

### サウンドファイルについて
`public/audio/` に以下のファイルを配置することで効果音・BGMが有効になります。

| ファイル名 | 用途 |
|---|---|
| `bgm_main1.mp3` 〜 `bgm_main3.mp3` | BGM（ゲーム中にランダム再生） |
| `se_card_play.mp3` | カードを出した時 |
| `se_believe.mp3` | 信じる |
| `se_doubt.mp3` | 疑う |
| `se_busted.mp3` | 嘘を見抜いた時 |
| `se_trust_broken.mp3` | 本当だった時 |
| `se_longshot.mp3` | LONGSHOT 発動時 |
| `se_win.mp3` | 勝利 |
| `se_lose.mp3` | 敗北 |

ファイルが存在しない場合もゲームは正常に動作します（無音で進行）。

## 🎯 開発背景・設計思想

### なぜ作ったのか
「ブラフ × イカサマ × 逆転要素」を軸に、**仲間とリアルタイムで遊べる心理戦ゲームが欲しかった**のが出発点。  
VTuber配信やパーティ向けに「爆発力のある演出」と「10〜15分で終わるテンポ感」を重視して設計した。

### エスカレーション制の意図
前のターンより大きい数字を宣言しなければならない「エスカレーション制」は、  
**「本当のカードを出せなくなる緊張の瞬間」** を自然に生み出すための仕組み。  
宣言できる範囲が狭まるほど嘘の可能性が読まれやすくなり、駆け引きが濃くなる。

### LONGSHOT の確率設計
- 確率は「宣言した数字（リスクの高さ）」によって変動する
- 小さい数字で嘘をついても奇跡はほぼ起きない
- 大きい数字ほどリスクも高いが、奇跡も起きやすい
- 「ハイリスク・ハイリターン」の構造を確率に組み込むことで、**勝負所でのロングショットへの賭け**がゲーム体験として自然に生まれる

### チート対策の難読化
確率計算式は意図的に難読化している。  
GitHubでソースが公開されても「何%で起きるか」をすぐに計算できないようにする、  
プレイヤーのドキドキ感を守るための設計。
